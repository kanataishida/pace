検証日：2026年9月24〜25日。v1.1.0でGalaxyの指紋認証向け案内・診断・認証確認を追加しました。画面とテストに使った金額・店名・借入はすべて架空の検証データです。通常起動するアプリにはデモデータを入れていません。

## 完成した範囲

React / TypeScript strict / Vite の端末内PWAとして、支出・収入・複数カード・引落・借入・返済・固定費・貯金・予算・履歴編集削除・残高照合・分析・データ管理・ロックを実装しました。未入力の金額を仮定しません。主な財務値は台帳から再計算します。

支出保存、分類学習、固定費の実績リンク、任意のお気に入り、下書き削除は同じIndexedDBトランザクションで確定します。バックアップ復元も全テーブルを一括で置き換えます。DB v2で入力下書き専用テーブルを追加し、家計の下書きもIndexedDBへ保存します。

## v1.1.0：Galaxyの指紋認証向け対応

WebAuthnのplatform authenticatorと本人確認必須の設定を維持し、特定メーカー名の判定で機能を無効化しません。HTTPS不足、IPアドレス、ブラウザAPI不足、利用可能な認証器なし、確認エラーを分けて案内します。端末設定から戻った際と手動操作で再確認し、登録後の「認証を試す」で実際に署名を検証します。

認証関連の単体テストは23件。実際に生成したP-256鍵のCBOR登録、署名検証、本人確認フラグなしの拒否、登録失敗時の既存PIN維持、ゼロカウンターとBE/BSフラグを持つ認証情報の連続利用を含みます。

AndroidのUser-Agent・モバイル画面とvirtual CTAP2 internal認証器で次を確認しました。

- 登録時はplatform・userVerification requiredを指定し、認証器に認証情報が作られること。
- 「認証を試す」で署名検証と成功表示が出ること。
- 再読み込み後はロックされ、認証の成功後だけホームを表示すること。
- 利用可能なplatform認証器がない場合、6桁PINを設定して再起動後に解除できること。
- 設定・ロック・PIN設定画面の360／412pxで横スクロールがなく、console error / pageerrorが0件であること。
- 本番PWAでService Worker有効化後に通信を遮断し、キャッシュから再起動して仮想認証器の署名検証で解除できること。

オフライン認証の試験では、再起動のHTMLがService Workerから返され、未キャッシュの試験用リクエストが通信遮断により失敗することを確認しました。使用したChromeでは再読み込み後に`navigator.onLine`がtrueを返したため、この値やバナー表示だけを通信可否の証拠にはしていません。想定した試験用リクエストの失敗以外にconsole error / pageerrorはありません。[認証試験の結果](galaxy-auth-results.json)

## 財務ロジック

カード購入5,000円は現金残高を減らさず、未払いと生活支出に加えます。後日の引落では現金残高と未払いがそれぞれ5,000円減り、生活支出は増えません。

固定費・返済・貯金の実行では、現金残高が減ると同時に対応する予定の確保額が減ります。同額で実行した場合、使っていい金額は二重に減りません。固定費をカードで払った場合は、固定費の確保額からカード未払いへ移ります。

```text
今使っていい金額
  = 現在使えるお金 − カード未払い − 未確認の固定費
    − 今月の未返済予定額 − 今月の未移動の貯金予定額

今日の目安
  = max(0, min(今使っていい金額, 今月の予算残り))
    ÷ 今日を含む月末までの日数（四捨五入）
```

予算がなければ、minの代わりに使っていい金額だけを使います。負のsafeToSpendも内部には保持します。残高の入力を後回しにした状態で支出・収入を記録しても、後で入力した「現在の実際の残高」に正しく合わせられます。

## ブラウザで確認した操作

- 初期設定を後回し → 支出記録 → 現在残高照合
- カード追加 → カード5,000円利用 → 5,000円引落
- 借入 → 今月の返済 → 確保額解放
- 貯金目標 → 実際の移動 → 確保額解放
- 固定費 → 支払確認 → 実績作成
- カード支出を現金へ変更、金額変更
- 支出削除 → Undo
- JSON保存 → 内容検証 → 復元
- PIN設定 → 再読み込み → PIN認証
- 仮想platform authenticatorでWebAuthn登録 → 再起動 → 署名検証による認証
- 支出入力シート、クイック入力、閉じた後の下書き保持
